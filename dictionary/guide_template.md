# FACE cohorts: a guide for researchers and coding agents

What facedata delivers for the four FACE cohorts, and what to know before an
analysis: the cohorts, their visits and traps, the instruments they share, the
subjects that they measure with different instruments, and the editions that

## 1. Start here

facedata reads the extraction of a cohort (a `.tsv` file, not part of the
package), checks it and returns harmonised tables:

```python
from facedata import bp          # or sz, dr, asp

result = bp.load("/path/to/BPALL_<date>.tsv", norms="/path/to/norms")
result.data         # one row per patient visit
result.patients     # one row per patient: sex, diagnosis, family history...
result.flags        # one row per cell that was changed or is doubtful, with the raw value
result.qc           # one row per variable: counts, range, flags
result.treatments   # one row per patient (or visit) and medication
result.relatives    # one row per patient and relative
```

- **A variable id is a column name** of one of these tables. What you pick in
  the dictionary is what you ask for. `load(instruments=[...])` loads only the
  instruments that you name (the field `instrument` of a variable).
- **The norm tables** (`norms=`) are copyrighted and not in the package. Only
  the standard scores read in a table (T-scores, percentiles, z-scores of some
  tests) need them: without them those are missing and `result.flags` says so.
  Sums and means of items (MADRS, QIDS, PSQI...) are computed without them.
- **Across cohorts:** `facedata.common.catalogue()` lists the instruments that
  two cohorts or more share, `facedata.common.instruments_of(cohort)` the
  instruments to load, and `facedata.common.baseline(result)` returns one row
  per patient (the inclusion visit, completed by the screening visit) and the
  visit that each instrument comes from.

Find a variable without opening a file:

| Command | What it does |
|---|---|
| `facedata guide --section 4` | Prints this guide, or one section of it (4, 5, 5.2...) |
| `facedata find depression --cohort dr --level score` | Variables whose id, label, meaning, instrument or construct holds every word |
| `facedata show madrs_total madrs` | The records of variables or instruments, as one JSON object (`--full` keeps the distributions) |
| `facedata instruments --cohort sz` | The instruments of a cohort; `--shared`: only those of two cohorts or more |
| `facedata page` | Opens the dictionary page in the browser: search, filters, cards, a basket that writes the `load()` code |
| `facedata files` | Where the guide, the JSON and the page are |
| `facedata init` | Writes the facedata block into AGENTS.md and CLAUDE.md of the current project |

In a uv project, run them as `uv run facedata ...`; anywhere, `python -m facedata ...`.
From Python: `from facedata import guide`, then `guide.find("depression", cohort="dr")`,
`guide.variable("madrs_total")`, `guide.instrument("madrs")`, `guide.instruments(cohort="sz")`.

## 2. Before an analysis

Read the record of every variable you use (`facedata show <id>`), and check:

- **`direction`** before putting variables on one scale or reversing one: what
  a higher value means, and how it is known. An item can run the other way
  from its score.
- **`harmonisation`** before stacking cohorts: `yes`, `with care` (read the
  note) or `no` (the same name, not the same thing).
- **`missing`, `timepoints` and `n.patients_2plus`** before a longitudinal
  model: which visits hold the variable, and how many patients have two values.
- **`edition`**: a variable read on some visits only (one edition or form of
  an instrument). Two editions never share a column (section 5.3).
- **The `flags` of the instrument** (`facedata show <instrument>`): its caveats,
  written by hand. The `flags` of a cohort block count the cells that facedata
  flagged (section 7).
- **`incomplete`** lists the fields that no source documents. An empty field
  means "not documented": say so, never fill it from memory.
- **A count of -1 means "fewer than 5"**; a percentage that would give such a
  count away is absent.
- **Scores are recomputed** from their items. When the database stored a score
  too, the two are compared (flag `score_mismatch`); where the stored score is
  wrong, the delivered one is the corrected score, and the notes of the schema
  say so.
- **Empty does not mean "no"**: an empty cell is not asked, not answered or not
  usable. A "no" is written 0.
- **Look at a variable per year and per centre** (`visit_date`, `siteid`)
  before concluding: the forms changed over the years and the centres do not
  fill them alike.
- **Extreme values of measures** are brought back to the 1st and 99th
  percentile (flag `winsorised`), except the vital signs and the ECG intervals;
  `load(winsorise=False)` keeps them as typed.

## 3. Patient data

The tables that `load()` returns are pseudonymised patient records.

- Report aggregates only. Never print, paste or commit rows of patients,
  their identifiers (`usubjid`, `fondacode`), their dates, or the values of a
  text column (free text can name a person).
- A count from 1 to 4 is not shown: write "fewer than 5".
- Do not name a centre in what you publish or commit; `siteid` is a code.
- The norm tables of the test manuals are copyrighted: never copy a value of
  them into code, notes or chat.
- A notebook is saved without its outputs: what appears under a cell is
  patient data.

## 5. Across cohorts

Each cohort module delivers the same patient columns (`cohort`, `usubjid`,
`visit`, `visit_order`, `visit_month`, `visit_date`, `siteid`, `age`) and the
same names for an instrument that cohorts share, so the tables of several
cohorts can be put under one another with `pd.concat` after reading the
verdicts below.

### 5.1 Instruments shared by two cohorts or more

Verdict (`stack`): **yes**, the same form, coding and scoring; **with care**,
read the note first; **no**, the same name or subject, not the same thing.
`use` names the variables to analyse across cohorts. A cohort column holds ✓
when the cohort has the instrument under the same id, its own id when it names
it otherwise, and – when it does not have it.

**The note of each instrument says what differs between the cohorts and what to
know first: read it before stacking** (`facedata show <instrument>`, field
`common.note`, or the instrument card of the page).

{shared}

### 5.2 The same subject, another instrument

The instruments of one row measure the same subject in different cohorts. They
are not on one scale and never share a column: a comparison needs a method of
its own (a z-score within the cohort, the cut-off of each instrument, a model).

{subjects}

### 5.3 Editions and forms

One instrument per edition or form, never two editions in one column. A
companion column says which edition a visit used.

{editions}

### 5.4 What each construct is measured with

The construct of each instrument, by area: the instruments of a construct in
each cohort. Use it to find every measure of one thing; `facedata find` with
the construct key lists its variables.

{constructs}
