# FACE cohorts: a guide for researchers and coding agents

What facedata delivers for the four FACE cohorts, and what to know before an
analysis: the cohorts, their visits and traps, the instruments they share, the
subjects that they measure with different instruments, and the editions that
must never share a column.

Built on 2026-11-23 from the data dictionary (362 instruments,
9,622 variables; git c83e6bc). This file is generated by
`dictionary/build_guide.py`: do not edit it.

**Contents:** 1. Start here · 2. Before an analysis · 3. Patient data ·
4. The cohorts · 5. Across cohorts · 6. Every instrument · 7. Flags ·
8. Further reading

## 1. Start here

facedata reads the extraction of a cohort (a `.tsv` file, not part of the
package), checks it and returns harmonised tables:

```python
from facedata import bp          # or sz, dr, asp

result = bp.load("/path/to/BPALL_<date>.tsv", norms="/path/to/norms")
result.data         # one row per patient visit
result.patients     # one row per patient: sex, diagnosis, family history...
result.flags        # one row per cell that was changed or is doubtful, with the raw value
result.qc           # one row per variable: counts, range, flags
result.treatments   # one row per patient (or visit) and medication
result.relatives    # one row per patient and relative
```

- **A variable id is a column name** of one of these tables. What you pick in
  the dictionary is what you ask for. `load(instruments=[...])` loads only the
  instruments that you name (the field `instrument` of a variable).
- **The norm tables** (`norms=`) are copyrighted and not in the package. Only
  the standard scores read in a table (T-scores, percentiles, z-scores of some
  tests) need them: without them those are missing and `result.flags` says so.
  Sums and means of items (MADRS, QIDS, PSQI...) are computed without them.
- **Across cohorts:** `facedata.common.catalogue()` lists the instruments that
  two cohorts or more share, `facedata.common.instruments_of(cohort)` the
  instruments to load, and `facedata.common.baseline(result)` returns one row
  per patient (the inclusion visit, completed by the screening visit) and the
  visit that each instrument comes from.

Find a variable without opening a file:

| Command | What it does |
|---|---|
| `facedata guide --section 4` | Prints this guide, or one section of it (4, 5, 5.2...) |
| `facedata find depression --cohort dr --level score` | Variables whose id, label, meaning, instrument or construct holds every word |
| `facedata show madrs_total madrs` | The records of variables or instruments, as one JSON object (`--full` keeps the distributions) |
| `facedata instruments --cohort sz` | The instruments of a cohort; `--shared`: only those of two cohorts or more |
| `facedata page` | Opens the dictionary page in the browser: search, filters, cards, a basket that writes the `load()` code |
| `facedata files` | Where the guide, the JSON and the page are |
| `facedata init` | Writes the facedata block into AGENTS.md and CLAUDE.md of the current project |

In a uv project, run them as `uv run facedata ...`; anywhere, `python -m facedata ...`.
From Python: `from facedata import guide`, then `guide.find("depression", cohort="dr")`,
`guide.variable("madrs_total")`, `guide.instrument("madrs")`, `guide.instruments(cohort="sz")`.

## 2. Before an analysis

Read the record of every variable you use (`facedata show <id>`), and check:

- **`direction`** before putting variables on one scale or reversing one: what
  a higher value means, and how it is known. An item can run the other way
  from its score.
- **`harmonisation`** before stacking cohorts: `yes`, `with care` (read the
  note) or `no` (the same name, not the same thing).
- **`missing`, `timepoints` and `n.patients_2plus`** before a longitudinal
  model: which visits hold the variable, and how many patients have two values.
- **`edition`**: a variable read on some visits only (one edition or form of
  an instrument). Two editions never share a column (section 5.3).
- **The `flags` of the instrument** (`facedata show <instrument>`): its caveats,
  written by hand. The `flags` of a cohort block count the cells that facedata
  flagged (section 7).
- **`incomplete`** lists the fields that no source documents. An empty field
  means "not documented": say so, never fill it from memory.
- **A count of -1 means "fewer than 5"**; a percentage that would give such a
  count away is absent.
- **Scores are recomputed** from their items. When the database stored a score
  too, the two are compared (flag `score_mismatch`); where the stored score is
  wrong, the delivered one is the corrected score, and the notes of the schema
  say so.
- **Empty does not mean "no"**: an empty cell is not asked, not answered or not
  usable. A "no" is written 0.
- **Look at a variable per year and per centre** (`visit_date`, `siteid`)
  before concluding: the forms changed over the years and the centres do not
  fill them alike.
- **Extreme values of measures** are brought back to the 1st and 99th
  percentile (flag `winsorised`), except the vital signs and the ECG intervals;
  `load(winsorise=False)` keeps them as typed.

## 3. Patient data

The tables that `load()` returns are pseudonymised patient records.

- Report aggregates only. Never print, paste or commit rows of patients,
  their identifiers (`usubjid`, `fondacode`), their dates, or the values of a
  text column (free text can name a person).
- A count from 1 to 4 is not shown: write "fewer than 5".
- Do not name a centre in what you publish or commit; `siteid` is a code.
- The norm tables of the test manuals are copyrighted: never copy a value of
  them into code, notes or chat.
- A notebook is saved without its outputs: what appears under a cell is
  patient data.

## 4. The cohorts

### FACE BP (bipolar disorder)

Adults with a bipolar disorder (type 1, type 2 or not otherwise specified), assessed in the FondaMental network of expert centres for bipolar disorder.

- **Patients:** 6,498; age at inclusion: median 39, quartiles 29 to 49 years.
- **`diagnosis`** (in `patients`): `bp1`, `bp2`, `bp_nos`.
- **Visits:** A screening record, then an inclusion visit (V0) and follow-up visits every six months or every year. Few patients are followed beyond five years.
  Visits in the extraction: screening 3,987, V0 6,498, V6_mois 2,301, V1_an 3,203, V18_mois 692, V2_ans 2,363, V30_mois 168, V3_ans 1,609, V42_mois 104, V4_ans 541, V54_mois 37, V5_ans 269, V66_mois 24, V6_ans 148, V78_mois 8, V7_ans 82, V90_mois 6, V8_ans 53, V102_mois fewer than 5, V9_ans 39, V114_mois 5, V10_ans 27, V126_mois fewer than 5.
- **Delivered:** 137 instruments, 2,528 variables; `data` 22,171 rows, `patients` 6,498 rows, `treatments` 22,758 rows, `relatives` 29,849 rows.
- **Extraction:** `BPALL_20261113_2.tsv`; figures computed on 2026-11-21.
- **Load it:** `from facedata import bp; result = bp.load(path)`.
- **Tutorial:** [bipolar-tutorial.ipynb](https://github.com/fondationfondamental/facedata/blob/main/bipolar-tutorial.ipynb).

The traps of this cohort:

1. `_v0` and `_fu` are two different questions: the inclusion visit asks about the whole life, the later visits about the time since the last visit or about an update of the inclusion form. Never put the two in one column.
2. Editions and forms have their own columns: WAIS-III and WAIS-IV, BIS-10 and BIS-12, the long and short ALS, WURS-25 and WURS-61, DSM-IV and DSM-5. A column such as `wais_version`, `bis_form` or `dsm_version` says which one a visit used.
3. Empty does not mean no: an empty cell is not asked, not answered or not usable. A no is written 0.
4. Sex, diagnosis and family history are in the table `patients`: join them to the visits on `usubjid`.
5. The screening visits hold only a few questionnaires (Altman, QIDS, MDQ). Start from V0.
6. Patients leave: a figure over time mixes change and departures.
7. Centres differ, and the forms changed over the years, most of all around 2022 (a "no for all" shortcut leaves the diseases of a section empty). Look at a variable per centre and per year before concluding.
8. The suicide answers of the follow-up visits of 2022 and 2023 are not delivered: the form of these two years asked about the whole life again.

### FACE SZ (schizophrenia)

Adults with schizophrenia, a schizoaffective or a schizophreniform disorder, assessed in the FondaMental network of expert centres for schizophrenia.

- **Patients:** 2,353; age at inclusion: median 30, quartiles 24 to 37 years.
- **`diagnosis`** (in `patients`): `schizophrenia`, `schizoaffective`, `schizophreniform`.
- **Visits:** A screening record (an EQ-5D only), an inclusion visit (V0) and yearly follow-up visits. Fewer than half of the patients are seen at one year.
  Visits in the extraction: screening 1,675, V0 2,353, V1_an 1,011, V2_ans 644, V3_ans 500, V4_ans 215, V5_ans 153, V6_ans 30, V7_ans 18, V8_ans 10, V9_ans fewer than 5, V10_ans fewer than 5.
- **Delivered:** 127 instruments, 2,063 variables; `data` 6,612 rows, `patients` 2,353 rows, `treatments` 11,038 rows, `relatives` 1,887 rows.
- **Extraction:** `SZALL_20261121.tsv`; figures computed on 2026-11-22.
- **Load it:** `from facedata import sz; result = sz.load(path)`.
- **Tutorial:** [schizophrenia-tutorial.ipynb](https://github.com/fondationfondamental/facedata/blob/main/schizophrenia-tutorial.ipynb).

The traps of this cohort:

1. `_v0` and `_fu` are two different questions (whole life, or since the last visit, or a yearly update of the inclusion form). Never put the two in one column.
2. WAIS-III and WAIS-IV have their own columns, for every subtest and every IQ; `wais_version` says which one a visit used.
3. Empty does not mean no: a no is written 0.
4. Some scores were wrong in the database and are delivered corrected (three PANSS factors, two WAIS-IV indices, the laterality quotient). Others are flagged: the CVLT z-scores of 2022 to mid-2025, and the Barona expected IQ, whose occupation is most often a copy of the diploma.
5. Some answers are lost by the export: no patient is married or living as a couple, no income is a salary, the Calgary scale has no item 9 and so no total, and `substance_disorder_v0` is missing on most inclusion visits (use the column of each substance).
6. Patients leave, centres differ, and the tests changed around 2015 to 2018 and part of the medical history in 2022: look at a variable per centre and per year.

### FACE DR (resistant depression)

Adults with a treatment-resistant major depressive disorder (TRD), assessed in the FondaMental network of expert centres for resistant depression. The inclusion criteria ask for a MADRS above 20.

- **Patients:** 634; age at inclusion: median 51, quartiles 41 to 60 years.
- **`diagnosis`** (in `patients`): `major_depressive_disorder`.
- **Visits:** A screening visit, a row of its own, then an inclusion visit (V0) and follow-up visits at 6, 12, 18 and 24 months and later. Half of the patients are seen at six months, a quarter at two years. The visits at 6 and 18 months are short: depression scales, weight and laboratory tests only.
  Visits in the extraction: screening 634, V0 634, V6_mois 298, V1_an 253, V18_mois 150, V2_ans 146, V30_mois fewer than 5, V3_ans fewer than 5, V4_ans 69, V5_ans fewer than 5.
- **Delivered:** 141 instruments, 2,812 variables; `data` 2,193 rows, `patients` 634 rows, `treatments` 1,633 rows, `relatives` 3,748 rows.
- **Extraction:** `DRALL_20261030.tsv`; figures computed on 2026-11-21.
- **Load it:** `from facedata import dr; result = dr.load(path)`.
- **Tutorial:** [depression-tutorial.ipynb](https://github.com/fondationfondamental/facedata/blob/main/depression-tutorial.ipynb).

The traps of this cohort:

1. The MINI, the Thase and Rush stage and the inclusion criteria are on the `screening` row of a patient, not on the V0 row. The MADRS is rated at both, on separate rows.
2. `_lifetime` and `_since_visit` are two different questions. Never put the two in one column.
3. Empty does not mean no, but a 0 in a box can mean not asked: in the MINI, the family form and the traumatic events, some boxes hold 0 wherever the form was opened. Look at the flag `derived_doubt`.
4. Since 2018 a simplified visit leaves out eleven self-questionnaires (STAI, Altman, MAThyS, Rosenberg, PSQI, Epworth, CSM, MARS, PRISE-M, BIS-10, BFI) and three clinician scales (YMRS, FAST, BAS). An empty scale is then not asked, and the extraction does not say which visits are simplified; some centres use it much more than others.
5. Some scores were wrong in the database and are delivered corrected: the CTQ, the BIS-10, the MARS, the SHAPS and the Fagerström total; the QIDS total is computed where the database stores none.
6. The medication lists are damaged: for a patient with several products there is no dose and no date, and the `on_...` columns are often empty.
7. Centres differ: look at a variable per centre and per year.

### FACE ASP (autism spectrum)

Children from 5 years and adults assessed for an autism spectrum disorder (Asperger syndrome and ASD) in the FondaMental network of expert centres. `diagnosis` says whether the centre confirmed the disorder (`asd_confirmed`) or not (`asd_not_confirmed`): both groups are delivered.

- **Patients:** 2,318; age at inclusion: median 20, quartiles 14 to 29 years.
- **`diagnosis`** (in `patients`): `asd_confirmed`, `asd_not_confirmed`.
- **Visits:** A screening record and an inclusion visit (V0). About one patient in ten has a follow-up visit. The dictionary of the cohort arrived after the module was written: every instrument was identified from the data, then checked against it.
  Visits in the extraction: screening 1,809, V0 2,318, V1_an 177, V2_ans 112, V3_ans 41, V4_ans 29, V5_ans 8, V6_ans fewer than 5, V7_ans fewer than 5, V9_ans fewer than 5.
- **Delivered:** 146 instruments, 4,769 variables; `data` 4,500 rows, `patients` 2,318 rows, `treatments` 7,129 rows, `relatives` 0 rows.
- **Extraction:** `ASPALL_20261030.tsv`; figures computed on 2026-11-21.
- **Load it:** `from facedata import asp; result = asp.load(path)`.
- **Tutorial:** [autism-tutorial.ipynb](https://github.com/fondationfondamental/facedata/blob/main/autism-tutorial.ipynb).

The traps of this cohort:

1. A child form and an adult form are two instruments with different columns and ranges: STAIC and STAI, CDI and BDI-II, BRIEF and BRIEF-A, the child and adult ADHD-RS. Never add them up or put them on one axis without saying so.
2. Two generations of forms: an old set of questionnaires until about 2017 (AQ, Empathy Quotient, RBS-R, Hamilton scales), a new set from 2019 to 2021 (RAADS-R, BDI-II, GSQ). An old scale is empty after the change because it was no longer asked.
3. The ADOS has four modules, each with its own columns and cut-offs; `ados_module` says which one was given.
4. The codes 7, 8 and 9 of the ADI-R and ADOS items are not levels. Never average the items: use the algorithm scores.
5. The centres do not give the same instruments: check that every centre fills a score before comparing them.
6. A treatment list belongs to a visit (in the other cohorts it is the history of the patient), and a missing list is not "no treatment".

## 5. Across cohorts

Each cohort module delivers the same patient columns (`cohort`, `usubjid`,
`visit`, `visit_order`, `visit_month`, `visit_date`, `siteid`, `age`) and the
same names for an instrument that cohorts share, so the tables of several
cohorts can be put under one another with `pd.concat` after reading the
verdicts below.

### 5.1 Instruments shared by two cohorts or more

Verdict (`stack`): **yes**, the same form, coding and scoring; **with care**,
read the note first; **no**, the same name or subject, not the same thing.
`use` names the variables to analyse across cohorts. A cohort column holds ✓
when the cohort has the instrument under the same id, its own id when it names
it otherwise, and – when it does not have it.

**The note of each instrument says what differs between the cohorts and what to
know first: read it before stacking** (`facedata show <instrument>`, field
`common.note`, or the instrument card of the page).

## 7. Flags

`result.flags` has one row per flagged cell, with the raw value; the record of
a variable counts its cells per flag.

| Flag | Severity | Meaning |
|---|---|---|
| `missing_code` | info | The cell held a missing code |
| `date_placeholder` | info | The date was a placeholder |
| `date_partial` | info | Day or month was unknown, or the day was replaced by the day that the export writes (`day`) |
| `format_repaired` | info | A number was written unusually but unambiguously |
| `censored_left` | info | The cell was `<limit`. For a band: this band or a lower one |
| `censored_right` | info | The cell was `>limit`. For a band: this band or a higher one |
| `band_from_z` | info | The band is the one a z-score has under the normal law: the z-score of the cell, or one computed with the regression of the norms |
| `unit_converted` | info | Converted from a labelled unit |
| `unit_inferred` | info | Unit taken from the magnitude; the label was missing, unknown or impossible |
| `sign_flipped` | info | A value stored in the other direction was turned (around the middle of its range, or multiplied by −1) |
| `version_inferred` | info | No version was recorded for the patient; it was taken from the inclusion date |
| `version_overridden` | info | The form labels the visit with one edition, a column that only another edition has is filled: the visit has the other edition |
| `visit_removed` | discrepancy | The visit has several impossible values in the instrument (`implausible_visits`): its block is shifted, so its other values are not delivered |
| `duplicate_row` | info | A duplicated visit record was dropped |
| `winsorised` | info | The value was clipped |
| `unit_doubt` | discrepancy | The value was possible under its label but fits another unit better |
| `sign_doubt` | discrepancy | The value is dated within 90 days of the day the direction changed, or has no date; or the visits of its centre and year lean to the other direction, not clearly enough to decide |
| `band_middle` | discrepancy | The cell held a band of values (`60-51`); the value is the middle of the band |
| `column_conflict` | discrepancy | Two raw columns of one variable hold different values; the first one listed is kept |
| `score_mismatch` | discrepancy | Stored and recomputed scores differ |
| `score_as_stored` | discrepancy | None of the items of the score is recorded: the score typed in the extraction is delivered, unchecked. Also a total built on such a score |
| `derived_doubt` | discrepancy | The value was computed by the EMR from a stored score that differs from the recomputed one |
| `patient_value_varies` | discrepancy | A patient-level variable, or an answer about a relative, changes between visits |
| `list_crossed` | discrepancy | An item of a list that the export crossed: the patient has several products, and the file does not say which dose or date belongs to which (SCHEMA_SPEC, section 15) |
| `visit_order` | discrepancy | Visit dates are not in visit order |
| `check_failed` | discrepancy | A custom check named in the schema failed, or a value is above the value it may not exceed on the same row (`not_above`) |
| `period_doubt` | discrepancy | The visit is dated in a period in which the schema says the column is not reliable |
| `period_removed` | danger | The visit is dated in a period in which the schema says the column is not reliable and asks for the value not to be delivered; `raw` holds what was written |
| `unparsed` | danger | The cell could not be read as its type |
| `unknown_code` | danger | A category value is not in the code list |
| `out_of_range` | danger | The value is outside the hard range. Also a visit date before the cohort opened or after today, an impossible age, and a date that must come before its visit on the day of the visit or later (`before_visit`) |
| `not_shown` | danger | The cell answers a question that the form did not show for the answer given (`shown_if`): a value the form wrote by itself; `raw` holds it |
| `unit_unknown` | danger | No usable unit label and the magnitude fits several units; or a percentage of a value that is missing |
| `version_unknown` | danger | Data present but version not recognisable |
| `norm_missing` | danger | No standard score could be read: the norm table was not found, or it has nothing for this age, raw score and second variable. For a z-score computed with a regression: the table was not found, or a variable of the regression is missing |
| `score_not_recomputed` | danger | The extraction stores the score but an item is missing: the score is not delivered; `detail` holds the stored value |
